# Native windows and popups

`Window` is now a prefab component derived from `UIBehaviour`. Instantiate the configured component instead of constructing a C# wrapper with `new Window { prefab = ... }`. Its `contentPane` is its own `RectTransform`; it no longer instantiates another content prefab.

Use `WindowBuilder.Configure` from a project postprocess to bake direct show/hide `Transition`, close button and drag area references. The builder adds the native drag receiver and its transparent raycast surface in the Editor. Optional references stay null. No runtime child names or controller names are resolved. Override `OnInit`, `OnShown` and `OnHide` for application behavior. Custom `DoShowAnimation`/`DoHideAnimation` overrides now return `UniTask` and complete when the animation ends. They must not call `OnShown` or `HideImmediately` themselves.

`ShowPopup` still accepts any `RectTransform`. A preconfigured `Window` on that root opts into its animations; an ordinary transform retains immediate show/hide. A targetless window with automatic placement keeps its authored position, while a supplied target or explicit direction uses normal popup placement.

Closing removes the popup and those above it from the logical stack immediately. A window remains visible until its hide animation finishes, stops blocking raycasts during that animation, then completes the `ShowPopup` task. Reopening a closing window cancels its previous task and supersedes the old animation; its old continuation cannot hide or complete the new session. Disabling or destroying a Window cancels its outstanding task; disabling Root cancels all outstanding popup tasks. Ordinary RectTransform popups use explicit Root dismissal for task completion. Callers awaiting a popup must handle cancellation, for example `await task.SuppressCancellationThrow()`. `HidePopupImmediately` completes dismissal without waiting for a hide transition and is used before disposal.

Use `PopupInputModule` in place of `InputSystemUIInputModule` on the existing `EventSystem`, with the same native action references. It subclasses the native module and checks mouse/pen pointer-down actions and the top `RaycastAll` result before native dispatch. There is no full-screen popup blocker or redispatched synthetic pointer event: clicking a lower popup closes only those above it, and clicking the page closes all popups while delivering that same click. Modal windows retain a separate blocking layer. `TogglePopup` ignores a popup closed by the current press, so the opener does not immediately reopen it on release; a subsequent press can reopen it. Explicit `ShowPopup` is allowed to reopen.

The module has no global input subscriptions and uses the native module's action enable/disable lifetime. Its precheck uses the public focus/background settings. The pointer precheck targets mouse/pen desktop UI. Multi-touch/tracked-device prechecks and the Editor's internal event-passthrough focus exception are not asserted; ordinary native navigation remains handled by the base module. A host that keeps the standard module does not acquire outside-click closing automatically.

The example uses separate `Assets/Scripts/DemoWindow1.cs` and `DemoWindow2.cs` files so each native component has a matching script name. Their former shared `DemoWindows.cs` is removed. `BasicsMain` holds typed component-prefab references and instantiates them with `Object.Instantiate`. The `BasicsExample` postprocess adds each component to its original window prefab, then bakes close/drag references. It also bakes the second example's content transition and its 0.3-second OutQuad scale show/hide transitions. Animation completion is handled by the existing SDK `Transition`; the example does not introduce a tween runner or runtime transition-name lookup. Run Migrate to apply these changed prefab types and references before opening the example. The reference implementation under `Assets/FairyGUI` is not a consumer to rewrite.

The candidate contains native PlayMode tests for animation completion, close/reopen races, a reentrant hide hook, lower-popup/page click-through, toggle suppression, modal ordering, module disable/reenable, and cancellation across Root/window disable. An Editor test saves and reloads the actual configured prefab references. The ten runtime cases and the prefab round-trip case have passed in the native Editor runner. The complete Demo and golden scenes still need separate migration and validation.


The pointer tests isolate virtual devices with the official Input System `InputTestFixture`, restore the previous mouse and leak-detection mode, and restore the previous EventSystem and background setting. They do not depend on Editor window focus. The existing golden tests and their rendering dependencies remain a separate validation step.

Managed Window dismissal calls OnHide after native deactivation has returned, so its callback can synchronously reopen the same Window. The outer replacement remains authoritative: it cancels the nested popup task and removes its temporary stack entry before creating its own session or converting it into a regular Window. Two native runtime regressions reproduce the previous engine activation error and duplicate/orphan entries; both now pass. This does not promise that Unity allows reactivating an object synchronously from an application-defined OnDisable callback.
